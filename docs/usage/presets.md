# 预设与场景过滤

从「规则」页右上角的预设入口，或「设置 → 高级功能 → 预设管理」进入。
核心通知过滤免费；预设与场景管理归入高级功能，当前原型开放体验，尚未接入支付。

## 保存与应用

- **关键词预设**：保存常用移除词、保留词，以及可选的应用范围。
- **场景预设**：在词库和应用范围之外，可设置生效时段与星期，例如工作日 09:00–18:00、每天 22:00–次日 08:00。不限定时段时，场景词持续参与匹配。
- 可从「减少营销打扰」「工作专注」「睡眠少打扰」模板开始编辑，保存为自己的预设。模板不会自动安装规则。
- **保存**仅更新预设库，不改变正在执行的规则。确认**应用**后，规则页和历史页上方会显示对应的「预设『名称』」规则。
- **关键词预设**可同时应用多个。**场景预设**使用“切换场景”：确认后停用其他场景，只保留所选场景；常用关键词预设、手动规则、全局开关及默认动作保留。整组规则一次保存，避免先清空后添加的中间状态。
- 页面上方显示已选择场景，仍受各自星期、时段和全局开关约束；“回到日常”只结束场景，常用关键词和手动规则继续工作。旧版已经叠加的多个场景会保留到第一次明确切换。
- 重复应用或切换同一预设会更新对应规则，不会重复添加。
- 编辑已应用的预设后，列表显示需要重新应用，运行中的旧版规则保持原状，直到再次确认应用。
- **停用**移除该预设产生的规则，保留预设本身；**删除**先停用，再删除保存的预设。两者均不删除手动规则或其他预设。

## 版本记录与回退

每次修改或删除预设前，自动保存旧定义。预设卡片右侧的“更多操作 → 保存命名版本”可另外保存一个带名称、时间的快照，例如“演示前”。所有预设共保留最近 20 条版本记录。

卡片菜单可查看该预设的版本，页顶工具菜单可打开“全部版本记录”，其中也包括已删除预设的历史。
查看旧词表、应用范围和时间后，点击“恢复这个版本”并确认，只恢复该预设到库中；其他预设及当前运行规则保留。
恢复后需要确认应用或切换场景，才更新运行规则。回退本身也会保留被替换的当前定义；已删除的预设可以恢复回库。

版本记录保存的是预设定义，不包含通知内容，也不是运行规则整库备份。

## 导入与导出

页顶“导入导出与版本”菜单支持“从文件导入”“粘贴 JSON 导入”“导出全部预设”；卡片菜单也可只导出单个预设。

- **导出**可复制 JSON，或通过 Android 系统文件选择器保存 `.json` 文件。不需要额外存储权限。
- **导入**先预览预设数量、移除词、保留词、范围和时间，再确认保存。同标识（ID）默认跳过，可选择更新本机版本；同名但不同标识会作为两个预设保留。
- 更新已有预设时，旧定义会自动进入版本记录。导入只入库，不启用过滤、不切换当前场景；已有运行规则继续使用原配置。
- 取消选择文件或取消确认不改库；非法内容、超过 100 项、文件超过 2 MiB、未来版本或过期预览会明确报错，不做部分导入。文件需为 UTF-8，兼容 BOM。

分享格式固定为 `{"schemaVersion":1,"presets":[...]}`，只包含当前词库及场景配置；不包含历史版本、通知记录或运行规则。内部 `presets.json` 的 v2 完整库不作为分享文件直接导入。

每个词按文本包含匹配，不是 AI 语义分类或正则。多个移除词任一命中即可；应用范围、词条件与时段之间必须同时满足。范围留空表示所有可监听的应用。

保留词生成保留规则，排在本预设的移除规则之前。多个预设叠加时，前面的保留规则也可能保留其他预设要移除的通知；完整执行顺序以「规则」页为准，首个匹配生效。“保留”动作没有独立的最高优先级。全局过滤关闭时，应用预设不会开启过滤；默认动作保持原状。

## 应用前批量对比

页顶工具菜单或单个预设的更多菜单可打开「批量效果对比」。选择一批历史记录，查看当前配置与应用该预设后的预计处理差异，不改变运行规则。
支持动作迁移矩阵、按应用统计、逐条命中解释及 JSON 导出，详见[批量对比说明](batch-comparison.md)。

## 场景时段

时段按设备当前本地时间，在每条新通知到达时由 Kotlin 引擎判断，不依赖 Flutter 页面或后台定时器。
跨夜窗口按**起始日**判断星期，例如仅选周五的 22:00–08:00，也包括周六早晨，周六晚上不在窗口中。
起点包含、终点不包含，起止时间不能相同。至少选择一个生效日。

这是所选场景的时间条件；应用内手动切换负责场景互斥，不会因时段结束自动改选另一个场景，也不会自动移除已有通知或重新发布之前移除的通知。现有通知监听授权和 Android 取消能力边界仍适用。

## 存储与失败处理

预设库独立保存在本机 `filesDir/presets.json`（schemaVersion 2），应用后的副本保存在现有 `rules.json`，关闭界面后仍由原生引擎处理。旧版 v1 可直接读取，第一次保存时迁移并保留 `.bak`。
预设库最多保存 100 项，当前定义不超过 2 MiB、含历史版本总库不超过 8 MiB，名称不超过 60 字；每组最多 100 个词、每词最多 100 字。应用不上传数据；导出位置由用户在系统选择器中选择。

原生存储使用同目录临时文件、同步写盘和原子替换，并保留最近一次 `.bak`。无法读取、损坏或未来版本的库会显示错误，禁止将其当作空库覆盖。
写入失败不会显示成功，表单和已有库仍保留。删除时若库写入失败，该预设可能已经停用，但仍保存在库中，可重试删除或重新应用。
旧版规则不含来源类型标记；修改预设类别时，会先仅迁移其规则标识，保留原条件、顺序、开关与行为，避免后续场景切换遗漏旧场景。新库保存失败时，规则标识迁移可能已经完成，但运行行为不变，可以重试。
