# 历史记录与拦截效果

历史页使用白底黑字、灰色边框和思源宋体，与生成器及黑白编辑界面保持一致。标题、底部导航、详情、筛选、规则效果和确认弹窗使用同一套配色与字体；字体复用生成器的原版 Source Han Serif SC Regular 资源，离线可用，OFL 许可证随包提供。处理结果同时使用文字和不同深浅的标签区分。

下拉刷新会重新读取本地最新记录和当前规则。右上角直接提供“清空”，确认后删除全部本地历史、将统计归零，并重置搜索、应用、处理结果、同规则筛选和日期范围，回到今天，便于下一轮演示。规则配置保留；取消确认不删记录。“更多操作”仍提供完整原始历史 JSON 导出和清空历史，导出复制到剪贴板。

每轮演示结束后，先在生成器点“清空通知”，再在历史页点“清空”。清空历史只删除记录，不会移除系统通知栏中仍存在的通知；监听继续运行，新到达的通知会产生新记录。

## 本次规则

历史页最上方显示“本次的拦截规则是”，按当前顺序列出启用规则的动作与名称，名称用【】标识。停用规则不显示；引擎关闭时明确显示全部保留；没有启用规则时按默认动作说明结果。进入历史页和下拉刷新时重读规则，在规则页修改开关后也会同步更新。

“查看具体条件”展示应用范围、匹配方式、关键词、可读渠道、正则、时段等实际配置。它说明当前规则，历史记录仍保留各条通知到达时的规则与处理结果，不根据现在的配置重算。

## 概览

可选今天、最近7天、全部记录。最近7天按本地日期计算，包含今天与之前六天。顶部展示：

- 拦截数：`action=intercept` 且 `cancelStatus=success` 的处理记录数。
- 拦截率：拦截数除以所选日期内的全部可见处理记录数，空数据为0%。
- 保留数：`action=allow` 的记录数。

失败、被系统拒绝、待确认或未执行移出的拦截记录不算成功，会单独提示。仅记录也单列，因此拦截数与保留数不一定加起来等于总数。卡片上的“未移出”等标记与实际取消状态对应，不能仅凭命中拦截规则声称通知已消失。

统计只覆盖本地仍保留的最近1000条记录，不保证覆盖全天或完整七天；按处理记录计数，同一通知多次更新可能有多条记录，不代表独立消息数，也不能推算节省时间或注意力提升。系统分组汇总不出现在列表和效果统计中，但原始记录与导出保持不变。设置页仍展示包含汇总的原始数量。

## 查找与详情

一次读取完整本地窗口后，在列表中搜索标题、正文、应用名称、包名或规则名称，无需回车。处理结果分类、应用筛选、同规则筛选和搜索都只作用于下方列表，不改变顶部所选日期的统计。时间范围会同时影响列表和概览。

点记录查看完整正文、实际结果、命中规则、可读渠道和记录时间。完整正文优先使用扩展正文；“更多信息”中保留原始包名、渠道ID、规则ID等。系统隐藏的内容仍按隐藏提示展示，不试图还原。查看记录不会恢复已取消的通知，也不承诺打开原会话。

“查看同规则记录”会清除搜索、应用和处理分类，按记录中当时的规则ID与动作筛选；当前日期范围不变。记录中的历史规则名和动作不会随当前规则的修改或删除而重算。只有缺少规则ID的旧记录才按历史名称与动作分组。

## 规则效果

展示每条规则的命中数、当时的处理动作和占全部记录的比例。拦截规则另显示确认移出成功的数量。规则动作固定，所谓单规则“放行率”通常只是0%或100%，因此不作为效果指标；命中占比也不是判断准确率。

点击某条规则可回查对应记录；“查看拦截记录”显示所有命中拦截动作的记录，其中未成功的记录明确标注。渠道中文名称与规则页共用一个展示函数，未改动原始ID、JSON协议或匹配逻辑。

## 验证

单元测试覆盖日期边界、超过100条后的搜索、统计与筛选分离、系统汇总排除、取消失败与成功区分、历史规则分组、清空与旧查询并发。页面测试覆盖完整正文、中文渠道、同规则回查、筛选、清空确认和320宽度的大字体布局。

本次不修改通知生成器、生成器契约、分流预设、E2E脚本或原生规则引擎。规则预览改用未筛选的原始历史窗口，避免历史页的搜索或日期选择影响创建规则时的预览样本。
