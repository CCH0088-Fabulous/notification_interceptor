# 简化规则创建

入口：底部“规则”→“新建规则”。创建流程为“应用范围 → 处理 → 预览”。规则局部使用白底黑字和 Noto Serif SC（Google/Adobe 同源宋体）；通过 Flutter google_fonts 下载并缓存，附 OFL 许可。通知内容不发送给字体服务。

## 可以创建的规则

- **所有应用 + 关键词**：不选软件，只要通知标题或内容出现任意一个词，就按所选动作处理。
- **指定应用 + 关键词**：先勾选一个或多个应用，应用和关键词必须同时满足。
- **指定应用 + 全部通知**：不检查正文，处理所选应用的全部新通知；可能包括重要信息，需谨慎使用。
- **主题快捷选择**：把主题展开成可增删的关键词。例如“促销购物”加入秒杀、降价、大促等。不是 AI，也不会识别没有出现这些词的同主题消息。

动作可选“自动移出”或“优先保留”。所有应用不能创建无关键词的全量规则。关键词去首尾空白、去重，英文不区分大小写；未按添加键的最后一个词在点击预览时也会加入。

## 预览与保存

预览取最近收到的最多 12 条真实通知（包括已进入会话/历史的通知），调用原生引擎计算整套候选规则，不会实际移出旧通知。显示预计处理结果和第一条命中规则。旧规则先命中时会明确提示。

新保留规则插在第一个移出规则之前；新移出规则放在末尾，旧规则相对顺序不变。编辑已有简单规则时保留原位置和启用状态。预览后基础规则若变化，保存会要求重新预览。保存失败不关闭向导，草稿仍在。

没有真实样本时，必须勾选“没有样本，仍保存规则”后才能保存，不能把这种情况当作验证成功。规则暂停时不会为了保存而自动开启。

复杂规则（渠道、正则、任一满足、时段、常驻条件等）继续进入原高级编辑器。规则页右上角“更多操作”中保留“高级创建”入口，生成器预设不会被简化界面覆盖或丢失字段。

## 已在实际测试中发现的平台边界

Android 15 会向部分通知监听应用隐藏检测到 OTP 等敏感内容的通知正文。本次模拟器中观察到正文变成 `Sensitive notification content hidden`，其中也包括一条促销消息。关键词和主题规则只能匹配系统实际提供的文字；不能保证识别正文被隐藏的通知。预览会提示这一点，不能把“无命中”理解为这条消息不重要。

“按应用全部处理”不依赖正文，但“先全部移出，再按关键词保留验证码”仍会因正文隐藏而失败，不能用来保证重要消息不漏。不要为获得全绿测试修改生成器或关闭系统敏感信息保护。

通知监听后移出不等于在发布前阻止声音/横幅。本次没有实现延后重发、语义识别、回复或通知恢复。

官方依据：[Android 15 行为变更：通知监听与 OTP 保护](https://developer.android.com/about/versions/15/behavior-changes-all#otp-redaction)。

## 复验与协作边界

`flutter test`：模型、页面、候选规则顺序、保存失败回滚、旧规则保护。`flutter analyze` 和 `dart run tool/check_layer_imports.dart`：静态与分层检查。

手动复验：在规则页创建“所有应用 + 关键词”“指定应用 + 关键词”“指定应用 + 全部通知”和“优先保留”规则，先用真实通知预览，再保存并发送新通知，核对实时页、历史结果与通知栏。已有生成器只代表一个真实包名；跨应用边界可用其他应用或现有 probe 补测，不能把生成器模拟类别当作不同应用。测试前备份规则，避免覆盖日常配置。

临时模拟器自动点击脚本受键盘输入与监听重连时序影响，已移出仓库，不作为稳定测试工具交付。历史开发期证据仅留在本地忽略目录 `docs/verification/reports/`。
生成器样本以 `GEN|post` 中的 `Category.keep` 为唯一分类期望来源。系统隐藏正文造成的失败照实记录；未解析到 ground truth 或出现无法解释的失败即中断。probe 的显式关键词/范围测试单独记录，不混算生成器分类结果。

未改动 `android/generator/**`、生成器测试、`GENERATOR_CONTRACT.md`、`assets/presets/generator_triage.json` 和 `tool/e2e.ps1`。未改变包名、tag、渠道或 JSON schema。实时与历史页面已修复通知快照解析、补充正文预览，并仅在展示层隐藏系统分组汇总。原始记录和导出不删除；历史统计仍包含汇总记录，实时会话计数则对应可见消息。

## 规则首页

顶部“新建规则”进入原有创建向导；右上角“更多操作 → 高级创建”进入高级编辑器。
卡片保留规则原名，展示应用范围、处理方式与条件。应用名称从已收到的通知读取，尚无名称时展示包名；已知生成器渠道显示中文别名，未知渠道保留原 ID。

“全部 / 保留 / 移出 / 已停用”只筛选显示，不排序、不修改规则。保留和移出分类按动作统计（包含停用规则）；已停用分类按开关状态统计。仅记录规则可以在“全部”中查看。卡片编号始终对应完整规则列表，首条匹配生效。

点击卡片展开详情，查看完整关键词、渠道 ID、正则、时段和条件组合；长内容可滚动查看。详情可以切换单条开关，或点“编辑规则”沿用原编辑流程。复杂条件仍进入高级编辑器。卡片右侧菜单保留编辑、删除及删除确认。全局关闭后所有规则暂停生效，不改变每条规则的开关状态。
